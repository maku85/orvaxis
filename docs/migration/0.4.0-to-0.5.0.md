# Migrating from 0.4.0 to 0.5.0

Version 0.5.0 was released on 2026-10-07. Most of it is additive; a few behaviors change in ways that can affect existing code, and they are listed first. The [changelog](https://github.com/maku85/orvaxis/blob/main/CHANGELOG.md) has the complete list. Upgrading from 0.3.1? Do [0.3.1 → 0.4.0](/migration/0.3.1-to-0.4.0) first.

```bash
npm install orvaxis@latest
```

## OpenAPI export is stricter

`generateOpenApiDocument` now raises a `TypeError` naming the route where 0.4.0 approximated or overwrote:

- **Wildcard routes** (`/files/*path`) used to appear as a path that is not a valid OpenAPI template. Exclude them explicitly: `exclude: (route) => route.path.includes("*")`.
- **Collisions** — the same operation twice, or templates differing only in parameter names (`GET /items/:id` with `POST /items/:itemId`) — are errors instead of overwriting.
- **Parameter names** such as `:user-id` are translated correctly; 0.4.0 rewrote them with a regular expression that recognized only letters, digits and `_`.
- **Converter output** with local references such as `#/$defs/x` is rejected; inline it or declare it in the new `componentSchemas` option and reference `#/components/schemas/<name>`.

If your OpenAPI generation worked in 0.4.0, run it once after upgrading: an error means the document it used to produce was wrong in that place. New and additive: a route-level `openapi` object (`operationId`, `summary`, `tags`, an optional `body`, media types) and the options above. See [OpenAPI export](/guide/openapi).

## Disconnected clients stop work

The built-in adapters now abort `ctx.req.signal` when the client disconnects before the response finishes, and the runtime stops before the next stage (middleware, handler) for such a request. The Express policy guard no longer calls `next()` after a disconnect, so an existing handler is not invoked late. A handler that did work for clients that had already left will now be skipped; shutdown still lets requests in progress finish. The abort reason is a standard `AbortError`. See [Timeouts and graceful shutdown](/guide/timeouts-and-shutdown).

## Shutdown honors `shutdownTimeout`

- **Fastify** now waits for streamed responses and destroys any still open at `shutdownTimeout`. In 0.4.0 `close()` returned at once and a stream could outlive it.
- **Express** no longer waits out `shutdownTimeout` after an in-flight stream ends itself: a response that finishes while the server is closing ends its connection instead of leaving an idle keep-alive socket.

If your process relied on `close()` returning early under Fastify, it now takes as long as the streams take, up to `shutdownTimeout`. A Fastify instance still cannot be reopened after `close()`.

## Policy traces keep the terminal decision

The decision that denied the request or failed evaluation is always recorded, even past `maxEvents` (which bounds the other decisions), so a truncated trace still explains the stop. A trace can therefore hold `maxEvents + 1` decisions. 0.4.0 dropped the terminal decision when the limit was already reached.

## `formatExecutionSummary` output

It shows the request method (with the matched route's method for HEAD → GET), the full route template including the group prefix, the status actually sent, and `Stopped by: <policy> (<id>)` with the new declaration ID. Code or tests that compare its text exactly need updating; 0.4.0 printed only the route's own path (`GET /:id` for a route declared as `/:id` in a group with prefix `/documents`), and the first line now shows the full template (`GET /documents/:id`). A throwing non-object value or a failure after a response was sent no longer breaks it.

## Types

`app.group()` is generic over the state and meta types, so handlers, middleware and policies annotated with `OrvaxisContext<AppState, AppMeta>` type-check when registered. No runtime change.

## New in 0.5.0

- `policyId` and `declarationIndex` on policy decisions, matching the IDs from `inspectRoutes()` ([Diagnose a 403](/guide/diagnose-403)).
- `buildRequestReport()`: a serializable, privacy-bounded report of one request ([reference](/reference/core-concepts#request-report)).
- `buildProtectionReport()`, `diffProtectionReports()` and Markdown formatters in `orvaxis/testing` ([CI article](/articles/authorization-requirements-in-ci)).
- Guides for execution, routing, middleware and hooks, typed validation, response contracts, OpenAPI, observability, plugins, request context, OpenTelemetry, HTTP adapters, streaming, timeouts and shutdown, and testing, plus a catalog of verified examples.
